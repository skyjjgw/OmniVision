# 项目交接文档

## 1. 文档目的
本文件用于帮助新的开发者、运维人员或协作者在不依赖原作者口头说明的情况下接手本项目。内容聚焦于仓库结构、硬件环境、运行依赖、配置入口、部署顺序和高风险注意事项。

## 2. 项目概述
视桥智导是一套面向视障人群的端云协同导盲系统，由三个端组成：

- 云端服务：负责业务接口、导航处理、场景描述、大屏与数据审核。
- 盲人端：负责边缘推理、语音交互、安全播报和设备侧实时响应。
- 志愿者端：负责人工求助、地图与社区功能。

核心设计原则如下：

- 高风险、低延迟逻辑优先在边缘端执行。
- 复杂环境理解和辅助表达由云端承担。
- 云端不能稳定判断时，允许人工兜底接入。

## 4. 硬件环境说明
### 4.1 盲人端硬件
- 主控板：Raspberry Pi 5
- 摄像头：MIPI-CSI 摄像头
- 音频输入：麦克风或麦克风阵列
- 音频输出：扬声器、耳机或骨传导设备
- 可选：GPS / 串口定位模块

### 4.2 云端环境
- Linux 云服务器或本地 Linux 主机
- Python 3.10
- Docker / Docker Compose
- 若启用稳定 WebRTC，建议额外部署 STUN / TURN

### 4.3 志愿者端设备
- Android 手机
- iPhone / iPad
- 本地 Flutter 调试设备或模拟器

### 4.4 选型原因
- Raspberry Pi 5 承担边缘推理，保证断网情况下仍具备基础导盲能力。
- MIPI-CSI 摄像头优先于 USB 摄像头，主要考虑更低延迟与更稳定的视频采集。
- 安全播报保留在端侧，防止云端延迟影响危险提示。

## 5. 三端职责边界
### 5.1 云端服务
- 目录：`apps/cloud-server`
- 关键入口：`backend.py`、`signaling_server.py`
- 主要职责：
  - 对外 HTTP API
  - WebSocket / Socket.IO 状态同步
  - 静态后台页面
  - 导航意图识别
  - 场景描述与审核逻辑

### 5.2 盲人端
- 目录：`apps/blind-client`
- 关键入口：`blind_client_pi5_csi.py`
- 主要职责：
  - 摄像头采集
  - 本地推理
  - ROI 安全播报
  - 流式 ASR / TTS
  - 设备侧自启动

### 5.3 志愿者端
- 目录：`apps/volunteer-app`
- 关键入口：`lib/main.dart`
- 主要职责：
  - 登录与用户交互
  - 人工接单
  - 地图与社区功能
  - 审核与反馈

## 6. 配置文件与敏感信息
本仓库已经删除真实密钥，只保留模板。

### 6.1 云端模板
- 路径：`shared/config/cloud.env.example`
- 需要补充：
  - LLM API Key
  - SMTP 邮件账号与口令
  - 后台账号密码
  - 公共访问地址

### 6.2 盲人端模板
- 路径：`apps/blind-client/.env.asr.example`
- 需要补充：
  - ASR App ID / Token
  - TTS Access Token / Access Key
  - 服务地址
  - 实际音频输入输出设备

### 6.3 志愿者端
- 运行时需配置服务 IP 和 TURN 凭据
- 参考模板：`shared/config/volunteer-app.env.example`

## 7. 新人第一次启动的建议流程
1. 克隆仓库
2. 复制并填写所有 `.example` 配置
3. 启动云端 API
4. 启动云端信令服务
5. 检查后台页面是否可访问
6. 启动盲人端并确认设备连接
7. 启动志愿者端并确认登录和网络联通

## 8. 常见故障点
- 云端后台能打开，但志愿者端无法通话：通常是 `signaling_server.py` 未启动。
- 盲人端能启动，但语音功能失效：通常是 `.env.asr` 未正确填写。
- 视频链路有明显延迟：优先检查摄像头接口是否被替换为 USB。
- 弱网下通话连接不稳定：优先检查 STUN / TURN 是否配置完整。
- 场景描述没有返回：优先检查云端 LLM Key 和公共访问地址。

## 9. 维护建议
- 配置永远通过模板或环境变量维护，不要把真实密钥重新写回源码。
- 运行数据、日志、上传文件、数据库文件不要直接提交到 Git。
- 若更换服务器 IP，需要同步更新三端配置。
- 若准备公开开源，请先明确许可证策略并新增 `LICENSE` 文件。
